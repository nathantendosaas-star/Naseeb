You are working inside an existing web app codebase. Your task is to add complete SEO indexing support for Google crawlability and search visibility, but only by creating/modifying files and code inside the project. Do not use any external services or dashboards. Do not assume the app’s existing route names, domain, framework, or file structure. Detect those from the codebase before making changes.

Goals:
1. Make the site crawlable by search engines.
2. Add a valid robots.txt.
3. Add a valid sitemap.xml.
4. Ensure the site exposes proper metadata for indexing and sharing.
5. Keep the implementation framework-appropriate and compatible with deployment on a modern static or server-rendered hosting setup.
6. Use placeholders anywhere real production values are unknown.

Important constraints:
- Do not assume any page names that are not already present in the app.
- Do not assume the domain. Use a placeholder like https://YOUR_DOMAIN when a real domain is required.
- Do not assume framework-specific file paths unless the codebase clearly indicates them.
- Do not create fake pages. Only include URLs for pages actually discovered in the codebase.
- Do not touch business logic unless needed for SEO.
- Do not alter design or UI except where metadata or head tags are required.
- Prefer a clean, minimal, reliable implementation over cleverness.

What to inspect first:
- Detect the framework and routing system used by the app.
- Discover all publicly accessible indexable routes from the codebase.
- Identify routes that should be excluded from indexing, such as:
  - auth pages
  - admin pages
  - internal dashboards
  - API routes
  - preview/test routes
  - error pages
  - duplicate routes
  - private or user-specific pages
- Determine whether the app uses static routes, dynamic routes, SSR, SSG, or a mix.
- Determine the best place in the project to expose static SEO files and metadata.

Required output/files:
1. robots.txt
   - Allow crawling of public pages.
   - Block non-indexable or private sections discovered in the app.
   - Point to the sitemap location using the placeholder domain if needed.
   - Keep it valid plain text.
   - Do not block the whole site.
   - Do not accidentally block CSS, JS, or image assets needed for rendering unless the codebase already requires it.

2. sitemap.xml
   - Generate a valid XML sitemap.
   - Include only public indexable routes discovered in the codebase.
   - Use canonical absolute URLs.
   - Use placeholders where the real domain is unknown.
   - Add lastmod values when possible.
   - Exclude private, duplicate, irrelevant, or non-indexable URLs.
   - Keep the XML standards-compliant.
   - If the app has many routes or dynamic routes, generate the sitemap dynamically or at build time if that is the cleanest fit for the framework.

3. SEO metadata in the app
   - Add or improve the default page metadata used across the site:
     - title
     - description
     - canonical URL
     - robots meta directives
     - Open Graph tags
     - Twitter card tags
   - Ensure each discovered important page can have its own metadata if the framework supports it.
   - Use safe placeholder values when page-specific copy is unknown.
   - Keep metadata consistent with the site’s actual purpose.

4. Structured data where appropriate
   - Add JSON-LD only if it fits naturally and does not require guessing facts.
   - Use placeholders for organization/site details if the real values are unknown.
   - Avoid adding speculative structured data.

Implementation requirements:
- Produce code that works with the app’s existing framework and routing conventions.
- If the framework supports a native sitemap/metadata API, use that.
- If not, create a simple reliable implementation that serves the correct files.
- If the app uses build-time generation, make sure sitemap generation is automated during build or deployment.
- If the app uses dynamic routes, include only valid canonical routes and make sure generated URLs are correct.
- Make sure the sitemap updates when routes change.
- Make sure robots.txt and sitemap.xml are reachable at their standard locations.

Quality requirements:
- Validate the XML syntax.
- Validate the robots.txt syntax.
- Do not create duplicate URLs in the sitemap.
- Ensure all sitemap URLs are absolute.
- Ensure metadata does not contain placeholder text in production-facing copy unless a real value is unknown.
- Do not break existing navigation or rendering.
- Keep code clean, readable, and documented.

Suggested behavior for route discovery:
- Scan the project for route definitions and page files.
- Build a list of publicly accessible routes.
- Convert those routes into canonical sitemap entries.
- Exclude routes that are clearly private, internal, or non-indexable.
- For dynamic routes, include only actual public canonical paths that are known from the codebase or generated content sources.

Suggested acceptance criteria:
- robots.txt is accessible and valid.
- sitemap.xml is accessible and valid.
- Public pages are included in the sitemap.
- Private/internal pages are excluded.
- The app has sensible default SEO metadata.
- Search engines can crawl the rendered pages cleanly.
- Nothing in the app depends on manual post-deployment editing.

Deliver the implementation directly in the codebase. Use placeholder values wherever real deployment values are unknown. Do not assume anything that is not supported by the existing project structure.
